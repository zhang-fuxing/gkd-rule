# 如何抓快照并添加跳过规则

面向场景：某个 App 的开屏广告或弹窗没被跳过，或者点了反而跳到广告页，需要新增 / 修正规则。

核心结论先说：**截图没用，必须用快照。** 截图只能看到按钮长什么样，看不到 `text` / `desc` / `vid` / `clickable` / 父容器层级——而这些才是规则能点准的唯一依据。

## 一、准备：开启悬浮窗

GKD → `设置` → `高级设置` → **`悬浮窗服务`**。

开启后屏幕上会出现一个可拖动的小圆钮，这就是抓快照的入口（后面酷狗截图底部中间那个圆形图标就是它）。

前置条件：

- 无障碍权限必须已开启（否则拿不到节点树，快照里没有节点信息）
- Android 11 及以上可直接截图；Android 10 及以下需要额外开启 `高级设置` → `截屏服务`

替代方案：把状态栏快捷开关里的「捕获快照」加到下拉菜单，效果一样。

## 二、抓快照

1. **让广告出现，但不要划掉它**（这点很关键，广告消失后节点就没了）
2. 点一下悬浮窗小圆钮
3. GKD 会提示已保存，快照进入 `快照` 记录列表

也可以在 GKD 里先打开 `设置` → `高级设置` → `快照`，确认里面已经能看到刚抓的记录。

## 三、上传，拿到 `i.gkd.li` 链接

GKD 里的快照默认只存在手机本地，要给别人（或者给 AI）看必须上传。上传需要先配置 GitHub Cookie：

1. GKD → `设置` → `高级设置` → `快照` → **`Github Cookie`**
2. 复制 Cookie 有两种方法：
   - 手机端：用 [Via 浏览器](https://viayoo.com) 打开 github.com 并登录 → 点地址栏左侧图标 → `查看 Cookies` → `复制文本`
   - 电脑端：浏览器登录 GitHub → F12 → `网络` → 刷新 → 点第一条 `github.com` 请求 → `标头` → 复制 `Cookie` 的值
3. 把 Cookie 粘贴进 GKD 保存
4. 回到快照记录，点该条快照的分享 / 上传，成功后得到链接：

```
https://i.gkd.li/i/18135562      ← 正确的分享链接
```

**注意**：从浏览器地址栏复制的 `https://i.gkd.li/snapshot/1734099604908` 是**本地链接**，别人打开只会显示「快照缺失」。必须用页面右上角分享生成的 `i.gkd.li/i/xxxxx`。

> 快照会公开到 GitHub，截图里可能有昵称、手机号、聊天记录。上传前先在相册里打码，然后在快照记录里替换截图。

## 四、在审查工具里定位节点

打开 `https://i.gkd.li/i/xxxxx`，这是网页版审查工具：

1. 左侧是节点树，点任意节点，右侧显示它的全部属性
2. 顶部搜索框可以直接输入 GKD 选择器，**实时高亮命中的节点**——这是最快验证写法的方式
3. 页面顶部会显示当前界面的 `activityId`，写规则时要用

要重点看的属性：

| 属性         | 用途                                              |
| ------------ | ------------------------------------------------- |
| `text`       | 按钮文字，如 `跳过`、`跳过 3`                     |
| `desc`       | 无障碍描述，很多 SDK 把按钮文字放这里             |
| `vid` / `id` | 资源 id，最稳定，如 `tt_splash_skip_btn`          |
| `clickable`  | **是否可点击，决定用 clickNode 还是 clickCenter** |
| 父节点       | 文字节点常不可点击，真正可点击的是它的父容器      |

## 五、写规则：先判断点哪个节点

这是最容易出错的一步。分三种情况：

**情况 1：按钮节点本身 `clickable=true`**

直接点它，默认 `action: 'click'` 会走节点点击，不受遮挡影响。

```ts
{
  matches: '[text="跳过"][clickable=true][visibleToUser=true]';
}
```

**情况 2：文字节点不可点击，但父容器可点击**

用 `@` 把点击目标指向父容器：

```ts
// @ 表示点击这个节点，而不是末尾的文字节点
{
  matches: '@[clickable=true] > [text*="跳过"][text.length<10]';
}
```

**情况 3：节点可点击但点击无效（被透明热区截获）**

显式指定节点级点击，绕过坐标：

```ts
{ action: 'clickNode', matches: '[text*="跳过"][height<300][visibleToUser=true]' }
```

**不要用固定坐标兜底。** `position` 按屏幕宽度比例计算，换机型、换广告创意、横竖屏都会偏，偏了就是点到广告本体。只有在完全没有节点可抓时才考虑，且必须在注释里写明限制。

## 六、把规则加进项目

### 先看这个 App 有没有现成文件

```bash
ls src/apps/<包名>.ts
```

**有文件**：说明是 `import-ref.ts` 自动生成的，直接改会被下次 `--all` 覆盖。要做的是在文件头加 `@manual` 标记，把它转为手工维护：

```ts
// @manual 手工维护: 补充了 xxx 布局的跳过按钮, --all 会跳过本文件
```

加标记后 `--all` 会打印 `[SKIP] ... 本地手工维护` 并跳过它。当前这样的文件只有一个：`com.kugou.android.ts`。

**没文件**：直接新建 `src/apps/<包名>.ts`，用下面的模板。

### 模板

```ts
import { defineGkdApp } from '@gkd-kit/define';

export default defineGkdApp({
  id: 'com.example.app',
  name: '示例应用',
  groups: [
    {
      key: 0,
      // 组名必须以「开屏广告」或「全屏广告」开头，否则不会被分类捕获
      name: '开屏广告',
      matchTime: 10000, // 只在进入 App 后 10 秒内参与匹配
      actionMaximum: 2, // 最多点 2 次, 给"点了没反应"留重试机会
      resetMatch: 'app', // 重新进入 App 时重置
      priorityTime: 10000, // 冷启动时优先匹配, 不被其它规则阻塞
      activityIds: '.app.splash.ForeNoBgSplashActivity', // 可选, 越精确越安全
      rules: [
        {
          key: 0,
          name: '跳过',
          matches:
            '[text*="跳过"][text.length<10][visibleToUser=true][height<300]',
          snapshotUrls: 'https://i.gkd.li/i/xxxxxxx', // 必填: 你刚抓的快照
        },
      ],
    },
  ],
});
```

### 三条硬性约定

1. **`activityIds` 能写就写**。省略表示该应用所有界面都匹配，误触风险高。activityId 从审查工具页面顶部或 GKD 触发记录里抄。
2. **正文字符串要加排除词**。`[text*="跳过"]` 会命中播放页的「跳过片头」，加 `[text!*="片头"]`，并用 `height<300` 排除大区块。
3. **`snapshotUrls` 一定要填**。它是这条规则唯一的验证凭据，也是以后改版排查的线索。

## 七、校验与发布

```bash
pnpm format      # 必须: 脚本/手写的源码都先格式化
pnpm check       # 类型检查 + 选择器语法校验
pnpm build       # 构建 dist, 版本号 +1
git add -A && git commit -m "feat(<包名>): 新增 xxx 开屏规则" && git push
```

推送后 CI 会再跑一遍校验并把 `dist` 提交回仓库，手机上 GKD 下拉即可拿到新版本。

## 八、排错对照表

| 现象                                 | 原因                                 | 处理                                             |
| ------------------------------------ | ------------------------------------ | ------------------------------------------------ |
| 触发记录里完全没有记录               | 规则没匹配                           | 检查 `activityIds`、`text`/`desc` 是否与快照一致 |
| 有记录，但广告没关                   | 点到了不可点击节点，或坐标被热区截获 | 改 `@` 指向父容器，或加 `action: 'clickNode'`    |
| 有记录，反而跳到广告页               | 点到广告本体（常见于点大容器的中心） | 缩小目标节点，去掉容器类选择器                   |
| 两条规则间隔约 100ms 先后命中        | 第一次点击无效，规则重试了           | 说明点击方式有问题，不是命中问题                 |
| 偶尔跳过、偶尔不跳                   | 不同广告创意的布局/热区不同          | 用节点选择器而非坐标；必要时按创意加多条规则     |
| 点了但只关掉一半（如关闭后又弹确认） | 多步流程                             | 用 `preKeys` 串联多个规则                        |

## 九、把链接发给 AI 时可以这样说

> 这是酷狗开屏的快照 `https://i.gkd.li/i/xxxxxxx`，跳过按钮没点中，帮我看看该点哪个节点。

有了链接，就能直接从节点树判断 `clickable`、父容器层级、热区位置，比截图猜快得多。
